Introduction to Web Development

A structured introduction to the technologies, concepts, architecture and terminology behind modern websites — from page structure and user interaction to servers, hosting and deployment.

SUBJECT: WEBSITE DESIGN & DEVELOPMENTLEVEL: FOUNDATIONAL TO INTERMEDIATEFORMAT: THEORY NOTES

Course Overview

Website design and development is the process of planning, designing, building, testing, publishing and maintaining websites and web applications. It combines visual communication, information structure, programming, data handling and internet infrastructure.

General Aim

To provide learners with a broad theoretical understanding of how websites are designed and developed, how frontend and backend systems work together, and how completed websites are hosted and made accessible through the internet.

Learning Outcomes

By the end of this unit, learners should be able to:

  • Explain website design, website development and the World Wide Web.
  • Describe the roles of HTML, CSS and JavaScript in frontend development.
  • Identify common markup languages, data formats and web standards.
  • Explain frontend and backend architecture and how they communicate.
  • Define synchronous and asynchronous programming and related terms.
  • Identify common frameworks, libraries, runtimes and development tools.
  • Explain server-side programming, databases, APIs and request processing.
  • Define hosting, domains, DNS, HTTP, HTTPS, SSL/TLS and deployment terminology.
  • Describe the basic stages involved in publishing and maintaining a website.

1. Introduction to Website Design and Development

Website

A website is a collection of related web pages and resources, usually identified by a common domain name and made accessible through the internet or a private network.

Website design

Website design is the planning and creation of a website's appearance, layout, navigation, content presentation and user experience. It considers how information should look and how visitors should interact with it.

Website development

Website development is the technical process of building a website. It includes writing code, creating page structures, implementing interactions, processing data, connecting databases, testing and preparing the website for use.

Website Design versus Website Development

Design focuses strongly on how a website is organised, presented and experienced. Development focuses on implementing the website's structure and behaviour using technologies and programming. In practice, the two activities overlap and must work together.

What is the World Wide Web?

The World Wide Web (WWW) is a system of interlinked documents and resources that people access over the internet using web browsers. It commonly uses URLs to identify resources and HTTP or HTTPS to transfer them. The Web is a service that operates over the internet; it is not another name for the entire internet.

Internet versus World Wide Web

The internet is the global network infrastructure connecting computers and other devices. The World Wide Web is one service that uses that infrastructure. Email, file transfer, voice communication and other services also use the internet without being the Web itself.

Important Basic Terms

  • Web page: an individual document or resource displayed by a browser.
  • Home page: the main or introductory page of a website, often the first page visitors encounter.
  • Web browser: application software used to request, interpret and display web content, for example Chrome, Firefox, Edge and Safari.
  • Web application: software accessed through a browser or web interface that provides functionality such as messaging, banking or online learning.
  • Hyperlink: a reference that allows a user to navigate from one resource to another.
  • URL — Uniform Resource Locator: the address used to identify and locate a resource on a network.
  • URI — Uniform Resource Identifier: a general identifier for a resource. A URL is a type of URI that also provides a means of locating the resource.
  • Responsive website: a website whose layout adapts to different screen sizes and device conditions.
  • Static website: a website that serves prepared files with little or no page content generated from user-specific or frequently changing data.
  • Dynamic website: a website whose content or behaviour can change according to data, user actions, application logic or server responses.
Core ideaA modern website is not simply a collection of attractive pages. It is a system in which content, presentation, interaction, data processing and internet infrastructure work together.

2. The Three Core Frontend Technologies

The frontend is the part of a website or web application that users directly see and interact with. It runs mainly in the user's browser and is responsible for presenting information and receiving user input.

HTML — Structure

Defines the meaning, organisation and content of a web page.

CSS — Presentation

Controls layout, colours, typography, spacing and visual appearance.

JavaScript — Behaviour

Provides logic, interaction, dynamic updates and browser-side processing.

Browser — Execution environment

Interprets the page technologies and displays the resulting interface.

2.1 HTML — HyperText Markup Language

Definition

HTML stands for HyperText Markup Language. It is the standard markup language used to describe the structure and meaning of content on web pages.

HyperText refers to text that can contain links to other documents or resources. Markup means adding labels or tags that describe the role and structure of content. Language refers to the defined set of elements and rules used to write that markup.

HTML terminology

  • Element: a complete HTML unit, commonly consisting of an opening tag, content and a closing tag. Some elements are void elements and do not have closing tags.
  • Tag: the markup written inside angle brackets, such as <p> or </p>.
  • Attribute: additional information written in an element's opening tag, such as href, src, id or class.
  • Semantic HTML: using elements according to their meaning, such as <header>, <nav>, <main>, <article> and <footer>.
  • DOM — Document Object Model: a programming representation of a document as a tree of objects that scripts can inspect and modify.
  • DOCTYPE: the declaration that tells the browser to use standards mode when interpreting an HTML document. Modern HTML documents begin with <!DOCTYPE html>.
  • Metadata: information that describes a document, such as its character encoding, viewport settings, title and description.
  • Form: an HTML structure used to collect user input through controls such as text fields, radio buttons, checkboxes and submit buttons.

Common HTML element groups

Document structure: html, head, body, title, meta.

Text: h1 to h6, p, strong, em, blockquote.

Navigation and media: a, img, audio, video.

Layout and meaning: header, nav, main, section, article, aside, footer.

Forms: form, label, input, textarea, select, option, button.

Why semantic HTML mattersMeaningful elements improve document organisation, accessibility, maintainability and the ability of search engines and assistive technologies to understand page content.

2.2 CSS — Cascading Style Sheets

Definition

CSS stands for Cascading Style Sheets. It is a style sheet language used to describe how HTML and other structured documents should be presented on screen, on paper or in other media.

Cascading refers to the process browsers use to resolve competing style rules. Style describes visual presentation, while a style sheet is a collection of rules that specify that presentation.

CSS terminology

  • Selector: identifies the HTML elements to which a CSS rule applies.
  • Declaration: a property and value written inside a CSS rule, such as color: navy;.
  • Property: the visual characteristic being controlled, such as font-size, margin or background-color.
  • Value: the setting assigned to a property, such as 16px, center or #ffffff.
  • Specificity: the weight browsers use when deciding which competing selector rule takes priority.
  • Inheritance: the process by which some CSS property values pass from a parent element to its descendants.
  • Box model: the layout model in which an element is represented by content, padding, border and margin.
  • Responsive design: designing layouts that adapt to available screen space and device characteristics.
  • Media query: a CSS condition that applies styles when characteristics such as viewport width or media type match.
  • Flexbox: a CSS layout model mainly used to arrange items along one dimension — a row or a column.
  • CSS Grid: a CSS layout model designed for two-dimensional layouts involving rows and columns.
  • Pseudo-class: a selector keyword that targets an element in a particular state, such as :hover or :focus.
  • Pseudo-element: a selector that targets a specific part of an element or creates a stylable generated part, such as ::before.

Ways of applying CSS

  • Inline CSS: styles written directly in an HTML element using the style attribute.
  • Internal CSS: styles written inside a <style> element in the HTML document.
  • External CSS: styles stored in a separate .css file and connected to HTML using a <link> element.
Why CSS exists separately from HTMLSeparating structure from presentation makes websites easier to redesign, maintain and adapt. One style sheet can control the appearance of many pages without repeating the same visual rules in every document.

2.3 JavaScript

Definition

JavaScript is a high-level, general-purpose programming language commonly used to make websites interactive and dynamic. It can run in browsers and in other environments, including server-side runtimes.

JavaScript terminology in web development

  • Event: an occurrence that code can detect, such as a click, key press, page load or form submission.
  • Event listener: code that waits for a specified event and runs a function when that event occurs.
  • Function: a reusable block of code designed to perform a task.
  • Variable: a named binding used to refer to a value.
  • Condition: an expression used to determine whether a particular path of code should run.
  • DOM manipulation: using JavaScript to inspect or change the document's elements, text, attributes or structure.
  • Validation: checking whether supplied data meets specified rules before it is accepted or processed.
  • Fetch API: a browser and runtime API used to make network requests and handle responses.
  • Client-side scripting: scripts executed in the user's environment, commonly the browser.

Typical uses of JavaScript on a website

  • Opening and closing navigation menus.
  • Validating form entries before submission.
  • Displaying messages and updating page content without a full reload.
  • Creating image galleries, sliders, tabs and interactive calculators.
  • Requesting data from a server and displaying the response.
  • Managing interactive application state, such as selected products or logged-in interface details.
Frontend relationshipHTML describes what the content is, CSS describes how it is presented, and JavaScript describes how the interface responds and changes. These roles are distinct, but the technologies cooperate.

3. Other Markup Languages and Data Formats

HTML is not the only language or format used to describe structured information. Some technologies mark up documents, some define data structures, and others describe interfaces or configuration. They should not all be classified as programming languages.

3.1 XML — Extensible Markup Language

Definition

XML stands for Extensible Markup Language. It is a markup language designed to store, structure and transport data using custom, descriptive tags.

Unlike HTML, which uses a standard set of elements to describe web content, XML allows document authors to define their own element names. XML is strict about correct nesting, closing tags and case.

Common terms: well-formed document (follows XML syntax rules), root element (the single outermost element), attribute (information attached to an element), namespace (a mechanism for avoiding naming conflicts), and parser (software that reads and processes structured XML).

<student>
  <name>Amina</name>
  <course>Web Development</course>
</student>

3.2 JSON — JavaScript Object Notation

Definition

JSON stands for JavaScript Object Notation. It is a lightweight text-based data-interchange format used to represent and exchange structured data between applications.

JSON is language-independent even though its syntax was inspired by JavaScript object notation. It is widely used when a browser communicates with a backend API. JSON supports objects, arrays, strings, numbers, Boolean values and null. Object property names and string values use double quotation marks.

{
  "student": {
    "name": "Amina",
    "course": "Web Development",
    "active": true,
    "subjects": ["HTML", "CSS", "JavaScript"]
  }
}

JSON object: an unordered collection of name/value pairs enclosed in curly braces. JSON array: an ordered list of values enclosed in square brackets. Serialization: converting data into a format suitable for storage or transfer. Deserialization: converting the transferred representation back into usable data.

JSON is not the same as a JavaScript objectJSON is text following a strict data format. A JavaScript object is an in-memory language value. JavaScript provides JSON.stringify() to convert suitable values to JSON text and JSON.parse() to parse JSON text.

3.3 XHTML — Extensible HyperText Markup Language

XHTML is a reformulation of HTML using XML syntax rules. It requires stricter document structure, including properly nested and closed elements. It was developed to bring HTML documents into an XML-based environment. Modern HTML is generally the normal choice for new websites.

3.4 SVG — Scalable Vector Graphics

SVG stands for Scalable Vector Graphics. It is an XML-based markup format for describing two-dimensional vector graphics. Vector graphics are defined using shapes, paths and mathematical descriptions, so they can scale without the pixelation associated with ordinary raster images.

3.5 MathML — Mathematical Markup Language

MathML represents mathematical notation and structure in a machine-readable form. It can be used to display mathematical expressions on the Web while preserving information about their structure and meaning.

3.6 XAML — Extensible Application Markup Language

Definition

XAML is a declarative, XML-based markup language used mainly in Microsoft's application-development technologies to describe user interfaces and, in supported frameworks, related objects and resources.

XAML is commonly associated with technologies such as Windows Presentation Foundation (WPF), Universal Windows Platform (UWP), and .NET MAUI. It is not a standard language for structuring ordinary web pages like HTML. It can describe interface elements such as windows, buttons, layouts and controls, while application code handles behaviour.

3.7 YAML — YAML Ain't Markup Language

YAML is a human-readable data-serialization language commonly used for configuration files. It represents data using indentation and key/value relationships. It is frequently encountered in deployment pipelines, application configuration and infrastructure tools. Indentation is significant.

application:
  name: student-portal
  port: 1750
  environment: development

3.8 Markdown

Markdown is a lightweight markup language that uses plain-text symbols to format headings, lists, links, emphasis and code blocks. It is commonly used for README files, technical documentation and notes.

3.9 Other related formats

  • RSS — Really Simple Syndication: an XML-based web feed format used to publish frequently updated content.
  • Atom: a web feed format used to distribute updates and content.
  • CSV — Comma-Separated Values: a plain-text tabular data format in which records are commonly separated by lines and fields by commas.
  • SQL — Structured Query Language: a language used to define, query and manipulate data in relational database systems. It is not a markup language.

4. Frontend Frameworks, Libraries and Tools

As websites become larger, developers often use libraries and frameworks to organise code, reuse solutions and manage complex interfaces.

Framework

A framework is a structured software foundation that provides conventions, tools and reusable components for building applications. It often guides how an application should be organised and may control parts of the application's execution flow.

Library

A library is reusable code that developers call when they need particular functionality. The application generally remains in control and chooses when to use the library.

Important distinction: a framework commonly provides a broader application structure, while a library usually provides focused functionality. The distinction is useful, although real tools may combine characteristics of both.

Common frontend frameworks and libraries

  • React: a JavaScript library for building user interfaces from reusable components. It is commonly used for interactive single-page applications and can also be used in larger application frameworks.
  • Angular: a TypeScript-based web application framework that provides an organised system for building large client applications.
  • Vue.js: a progressive JavaScript framework for building user interfaces. It supports component-based development and can be adopted gradually.
  • Svelte: a UI framework that uses a compiler to transform component code into efficient JavaScript.
  • Bootstrap: a frontend toolkit containing CSS and JavaScript components, layout utilities and responsive design features.
  • Tailwind CSS: a utility-first CSS framework that provides small, composable classes for styling elements directly in markup.
  • jQuery: a JavaScript library that historically simplified DOM manipulation, event handling and AJAX requests. Many tasks it once simplified are now supported by modern browser APIs.

Related frontend concepts

  • Component: a reusable, self-contained part of an interface, such as a navigation bar, card or form.
  • SPA — Single-Page Application: an application that loads an initial page and updates much of its interface dynamically as users navigate or interact.
  • MPA — Multi-Page Application: a website structure in which navigation commonly requests separate documents or pages from the server.
  • Routing: matching a URL or navigation action to the page, view or handler that should respond.
  • State: information that describes the current condition of an interface or application, such as selected items or form status.
  • Props — properties: input values passed from a parent component to a child component in component-based UI systems such as React.
  • Virtual DOM: a programming representation of UI structure used by some libraries to calculate and apply interface updates.
  • Bundler: a development tool that processes and combines application modules and assets for delivery, for example Vite or webpack.
  • Transpiler: a tool that converts source code from one language version or syntax form into another, for example TypeScript being transformed into JavaScript.

Common frontend development tools

  • Code editor: software used to write and organise source code, for example Visual Studio Code.
  • Browser developer tools: built-in browser facilities for inspecting HTML, CSS, network requests, storage, performance and JavaScript execution.
  • Git: a distributed version control system used to track changes in source code.
  • Package manager: a tool that installs and manages software dependencies, such as npm, pnpm or Yarn.
  • npm: commonly refers to the package manager and package registry ecosystem used with JavaScript and Node.js.
  • Node.js: a JavaScript runtime that allows JavaScript to execute outside the browser. It is also widely used to run frontend development tools.
  • Vite: a frontend development and build tool that provides a development server and production build process.
Frameworks do not replace the fundamentalsDevelopers need to understand HTML, CSS, JavaScript, browser behaviour and HTTP before relying heavily on frameworks. A framework organises development; it does not remove the underlying web platform.

5. Backend Development

Backend

The backend is the part of an application responsible for server-side processing, business rules, data access, authentication, authorisation and communication with other systems. It is not normally displayed directly as the user interface.

When a visitor submits a form, signs in, searches for a record or places an order, the browser may send information to a backend. The backend checks the request, applies application rules, interacts with databases or other services and returns an appropriate response.

Frontend versus backend

The frontend presents the interface and gathers user actions. The backend processes requests and manages protected application operations and data. A complete web application normally needs both sides to cooperate.

Common backend responsibilities

  • Receiving and processing HTTP requests.
  • Validating incoming data and enforcing business rules.
  • Authenticating users and checking their permissions.
  • Reading from and writing to databases.
  • Generating responses, reports and documents.
  • Communicating with payment, email, identity or other external services.
  • Recording logs and handling errors.

Backend terminology

  • Business logic: the rules that define how an application should operate, such as admission eligibility or fee calculations.
  • Endpoint: a specific URL and HTTP method combination through which an API exposes an operation.
  • API — Application Programming Interface: a defined way for software systems or components to communicate and use one another's functionality.
  • REST — Representational State Transfer: an architectural style for networked systems. REST APIs commonly use HTTP methods and resource-oriented URLs.
  • CRUD: Create, Read, Update and Delete — the four basic operations commonly performed on stored records.
  • Middleware: software that runs between the arrival of a request and the final route or response handler. It can perform tasks such as logging, parsing, authentication and validation.
  • Authentication: verifying who a user or system is.
  • Authorisation: deciding what an authenticated identity is permitted to do.
  • Session: a mechanism for maintaining information about a user's interaction across multiple requests.
  • Cookie: a small piece of data stored by a browser and sent with matching requests according to its settings.
  • Token: a value used to represent or prove a particular identity, permission or claim. A token must be protected against theft and misuse.
  • JWT — JSON Web Token: a compact token format for representing claims between parties. A JWT is commonly signed; signing does not automatically encrypt its contents.
  • Environment variable: a value supplied to a running process from its environment, often used for configuration such as ports or secret references.
  • Logging: recording events and diagnostic information to help monitor and investigate application behaviour.

Backend languages and runtimes

  • JavaScript with Node.js: uses JavaScript outside the browser to build APIs, web servers and backend applications.
  • TypeScript: a typed superset of JavaScript that adds compile-time type checking and is transformed into JavaScript for execution.
  • Python: a general-purpose programming language used for backend development, automation, data processing and many other tasks.
  • PHP — PHP: Hypertext Preprocessor: a server-side scripting language widely used in web development.
  • C#: a general-purpose language commonly used with the .NET platform to build web APIs and other applications.
  • Java: a general-purpose programming language commonly used with server-side frameworks such as Spring.
  • Ruby: a general-purpose language used in web development, notably with Ruby on Rails.

6. Backend Frameworks and Common Packages

Backend frameworks provide structures for receiving requests, organising routes, applying middleware, validating information and producing responses.

  • Express.js: a minimal web framework for Node.js used to build web servers and APIs.
  • NestJS: a Node.js framework, commonly using TypeScript, that provides a structured architecture for server-side applications.
  • Fastify: a Node.js web framework designed for efficient request handling and a plugin-based architecture.
  • Django: a high-level Python web framework that includes many built-in facilities for common web application requirements.
  • Flask: a lightweight Python web framework that provides a smaller core and allows developers to add extensions as needed.
  • FastAPI: a Python framework for building APIs with type hints and automatic interactive API documentation support.
  • Laravel: a PHP web application framework providing tools for routing, database access, authentication and other common tasks.
  • ASP.NET Core: Microsoft's cross-platform framework for building web applications and APIs using .NET, commonly with C#.
  • Spring Boot: a Java-based framework that simplifies the creation of stand-alone, production-oriented applications built with the Spring ecosystem.
  • Ruby on Rails: a Ruby web application framework that emphasises conventions and developer productivity.

Framework versus runtime versus package

  • Runtime: the environment that executes a program, such as Node.js for JavaScript outside a browser.
  • Framework: a structured foundation that guides application organisation and execution.
  • Library: reusable code called by an application to perform particular tasks.
  • Package: a distributable unit of software, commonly containing code, metadata and dependencies.
  • Dependency: an external package or module that an application relies on.
  • Module: a reusable unit of code that can expose functionality for other parts of a program to use.
Example architectureA browser can display an HTML/CSS/JavaScript interface. The interface sends an HTTP request to an Express.js application running on Node.js. The application validates the request, accesses a database and returns a JSON response.

7. Data Exchange, HTTP and APIs

HTTP — HyperText Transfer Protocol

Definition

HTTP stands for HyperText Transfer Protocol. It is an application-layer protocol used for communication between clients and servers on the Web. It defines how requests and responses are structured.

A client is the system that initiates a request, commonly a browser. A server is the system that receives the request and provides a response or service.

HTTP request

An HTTP request is a message sent by a client asking a server to perform an operation or provide a resource. It commonly contains a method, URL, headers and, where needed, a body.

HTTP response

An HTTP response is the message returned by a server. It commonly contains a status code, headers and an optional body containing HTML, JSON, an image or another representation.

Common HTTP methods

  • GET: requests a representation of a resource. It is intended for retrieval.
  • POST: submits data for processing, often creating a resource or triggering an operation.
  • PUT: creates or replaces the state of a resource at a specified target URI, depending on the API design.
  • PATCH: applies a partial modification to a resource.
  • DELETE: requests removal of a specified resource.
  • OPTIONS: asks about communication options supported for a resource or server.

HTTP status codes

  • 1xx — Informational: the request has been received and processing is continuing.
  • 2xx — Success: the request was successfully received, understood and accepted.
  • 200 OK: the request succeeded.
  • 201 Created: the request succeeded and resulted in a resource being created.
  • 204 No Content: the request succeeded but the response has no content body.
  • 3xx — Redirection: further action is needed, commonly to access another location.
  • 400 Bad Request: the server cannot process the request because it is invalid or malformed.
  • 401 Unauthorized: valid authentication credentials are missing or unacceptable. Despite the name, it concerns authentication.
  • 403 Forbidden: the server understands the request but refuses to authorise it.
  • 404 Not Found: the requested resource or route was not found.
  • 405 Method Not Allowed: the method is not supported for the target resource.
  • 409 Conflict: the request conflicts with the current state of a resource.
  • 422 Unprocessable Content: the content is understood but cannot be processed according to the application's rules.
  • 429 Too Many Requests: the client has sent too many requests within a given period.
  • 5xx — Server Error: the server failed to fulfil an apparently valid request.
  • 500 Internal Server Error: an unexpected server-side failure occurred.
  • 502 Bad Gateway: a gateway or proxy received an invalid response from an upstream server.
  • 503 Service Unavailable: the server is temporarily unable to handle the request.
  • 504 Gateway Timeout: a gateway or proxy did not receive a timely response from an upstream server.

Headers, body and content type

  • HTTP header: metadata sent with a request or response, such as content type, accepted formats or caching instructions.
  • Request body: data sent by a client, commonly with POST, PUT or PATCH.
  • Response body: the content returned by the server.
  • MIME type: a media type label identifying the format of content, for example text/html, text/css, application/javascript or application/json.
  • Content-Type: an HTTP header that identifies the media type of the message body.
  • Accept: a request header indicating which response media types the client can process.

API communication

An API allows one software component to request functionality or data from another through an agreed interface. A web API commonly exposes endpoints over HTTP. The client and server agree on methods, URL patterns, request formats, response formats and error behaviour.

AJAX — Asynchronous JavaScript and XML

AJAX is a web-development approach in which JavaScript communicates with a server asynchronously and updates parts of a page without requiring a complete page reload. Despite the historical word XML in its name, modern AJAX-style communication commonly uses JSON and the Fetch API.

CORS — Cross-Origin Resource Sharing

CORS is a browser security mechanism that uses HTTP headers to determine whether a web page from one origin may access resources from another origin. An origin is the combination of scheme, host and port. CORS is not a replacement for authentication or authorisation.

8. Synchronous and Asynchronous Programming

Synchronous programming

Synchronous execution follows an ordered process in which an operation must complete before the next dependent operation proceeds. The current flow waits for that operation to finish.

Asynchronous programming

Asynchronous programming allows an operation to be started without requiring the surrounding program flow to remain blocked until the operation completes. The program can continue other work and handle the result later.

Why asynchronous programming is important

Web applications frequently wait for external operations such as network responses, database queries, file access and timers. These operations may take an unpredictable amount of time. Asynchronous techniques help applications remain responsive while waiting for such work.

Blocking and non-blocking operations

  • Blocking operation: prevents the current execution flow from proceeding until the operation finishes.
  • Non-blocking operation: allows the program to continue while the operation is being completed elsewhere or scheduled for later handling.

Callback

A callback is a function passed to another function so that it can be called later, often when an operation finishes or an event occurs. Callbacks are one way of handling asynchronous operations.

Promise

A Promise is a JavaScript object representing the eventual success or failure of an asynchronous operation. Its main states are pending, fulfilled and rejected. A settled Promise is either fulfilled or rejected.

async and await

async is a JavaScript keyword used to define a function that returns a Promise. await is used within an async function, or supported module contexts, to pause that function's progress until a Promise settles. It does not normally block the entire JavaScript runtime.

Event loop

The event loop is a mechanism used by JavaScript environments to coordinate execution of queued tasks and asynchronous callbacks. It allows JavaScript to handle events and asynchronous results while maintaining its execution model.

Concurrency and parallelism

  • Concurrency: managing multiple tasks whose execution periods overlap. The tasks may make progress in turns rather than literally running at the same instant.
  • Parallelism: executing multiple tasks at the same instant, commonly using multiple CPU cores or workers.
Important distinctionAsynchronous does not automatically mean parallel. A program can handle asynchronous network operations without executing JavaScript instructions on multiple CPU cores at the same time.

9. Databases and Data Storage in Web Applications

Database

A database is an organised collection of data stored so that it can be accessed, managed, updated and retrieved efficiently.

Database management system

A DBMS — Database Management System is software used to define, create, store, query, update and control access to databases. It manages data operations and helps enforce integrity and security rules.

Relational databases

A relational database organises data into tables made up of rows and columns. Tables can be connected using keys and relationships. Examples include MySQL, PostgreSQL, SQLite and Microsoft SQL Server.

NoSQL databases

NoSQL is a broad term for database systems that use data models other than the traditional relational table model, or provide alternative approaches to data organisation and access. Examples include document, key-value, wide-column and graph databases.

Common database terms

  • Table: a structured collection of related records in a relational database.
  • Record / row: one stored entry in a table.
  • Field / column: a named attribute in a table.
  • Primary key: a column or combination of columns that uniquely identifies a row.
  • Foreign key: a column or combination of columns that references a key in another table or the same table.
  • Query: a request to retrieve or manipulate data.
  • SQL: Structured Query Language, used with relational database systems.
  • ORM — Object-Relational Mapper: a tool that maps application objects or models to relational database structures and operations.
  • Connection pool: a managed set of reusable database connections that reduces the cost of repeatedly opening new connections.
  • Transaction: a group of database operations treated as one logical unit, with commit and rollback behaviour.
  • ACID: Atomicity, Consistency, Isolation and Durability — properties used to describe reliable database transactions.

Common database technologies

  • MySQL: an open-source relational database management system widely used in web applications.
  • PostgreSQL: an advanced open-source object-relational database management system.
  • SQLite: a lightweight, embedded relational database engine that stores a database in a file.
  • MongoDB: a document-oriented NoSQL database that stores records in BSON, a binary-encoded JSON-like format.
  • Microsoft SQL Server: a relational database management system developed by Microsoft.

10. Server-Side Programming

Server-side programming

Server-side programming is the development and execution of application logic on a server or server runtime rather than directly in the user's browser. It handles requests, applies rules, accesses protected resources and prepares responses.

Server

A server is a computer system or software process that provides resources or services to other systems, called clients. A physical server is hardware; a server application is software that listens for and handles requests. One physical machine can run many server processes.

Web server

A web server is software, and sometimes the computer running it, that accepts HTTP requests and serves web resources or forwards requests to application software. Common web server software includes Nginx, Apache HTTP Server and Microsoft IIS.

Application server

An application server runs application logic and provides services required by an application. In many modern deployments, the application process handles business logic while a separate web server or reverse proxy receives public traffic and forwards requests.

Reverse proxy

A reverse proxy is a server positioned in front of one or more backend servers. It receives client requests and forwards them to the appropriate internal service. It may also handle TLS termination, compression, caching, routing and load balancing.

Load balancer

A load balancer distributes incoming traffic across multiple servers or application instances to improve availability, capacity and performance.

Server-side rendering and client-side rendering

  • SSR — Server-Side Rendering: the server generates HTML for a page and sends it to the browser.
  • CSR — Client-Side Rendering: the browser uses JavaScript to construct or update much of the interface after receiving the application resources.
  • SSG — Static Site Generation: pages are generated into static files before users request them, often during a build process.
  • Hydration: attaching client-side JavaScript behaviour to HTML that was already rendered, commonly by a server or build process.

Server-side request lifecycle

  1. A user performs an action in the browser.
  2. The browser constructs an HTTP request and sends it over the network.
  3. The server or reverse proxy receives the request.
  4. The application routes the request to the appropriate handler.
  5. Middleware may parse the body, log the request and perform security checks.
  6. The application validates input and applies business rules.
  7. The application may query a database or communicate with another service.
  8. The server creates an HTTP response with an appropriate status code and body.
  9. The browser receives the response and updates the interface.
Server-side security principleNever assume that data is safe because a browser form checked it. A user can bypass the interface and send a request directly. The backend must independently validate input, enforce permissions and protect secrets.

11. Hosting, Domains and Internet Infrastructure

After a website has been developed and tested, it needs an environment where its files or application can run and a way for visitors to locate it. This stage introduces infrastructure and networking terminology.

Hosting

Web hosting

Web hosting is a service or infrastructure arrangement that provides storage, computing resources and network access for making a website or web application available to users.

A hosting provider may supply storage, server processing, databases, network connectivity, security features, backups and management tools. Hosting is not the same as a domain name: hosting provides the environment, while a domain provides a human-readable address.

Common hosting types

  • Shared hosting: multiple websites use resources on the same hosting server. It is often inexpensive but offers less control over the environment.
  • VPS — Virtual Private Server: a virtual server with allocated resources and an operating-system environment hosted on shared physical hardware.
  • Dedicated server: a physical server allocated to one customer or organisation.
  • Cloud hosting: hosting that uses a pool of connected computing resources and can offer flexible scaling and availability.
  • Managed hosting: a service where the provider takes responsibility for specified server administration tasks.
  • Static hosting: hosting designed to serve static files such as HTML, CSS, JavaScript, images and documents.
  • Serverless hosting / computing: a cloud model in which the provider manages server infrastructure and runs code or services on demand. Servers still exist; their management is abstracted from the application developer.

Domain name

Definition

A domain name is a human-readable name used to identify an internet resource or network location, such as example.com.

Domain names are organised hierarchically and are resolved through the Domain Name System. Registering a domain gives the registrant rights to use that name for the registration period, subject to the registrar's and registry's rules.

Domain terminology

  • TLD — Top-Level Domain: the highest level in the public domain name hierarchy, such as .com, .org or .ug.
  • ccTLD — Country-Code Top-Level Domain: a top-level domain associated with a country or territory, such as .ug for Uganda.
  • gTLD — Generic Top-Level Domain: a top-level domain category not assigned as a country code, such as .com or .org.
  • Second-level domain: the label directly below the TLD in a domain name, such as example in example.com.
  • Subdomain: a label added before the main registered domain, such as admissions in admissions.example.com.
  • Registrar: an organisation authorised to register domain names for customers.
  • Registry: the organisation responsible for maintaining the authoritative database for a particular top-level domain.
  • WHOIS / RDAP: systems used to access domain registration information. RDAP means Registration Data Access Protocol and is the modern standard replacing many traditional WHOIS services.

DNS — Domain Name System

Definition

DNS stands for Domain Name System. It is the distributed naming system that translates domain names into information needed to locate services on the internet, commonly including IP addresses.

An IP address is a numerical network address assigned to an interface or resource. IPv4 uses 32-bit addresses, commonly written in dotted-decimal form. IPv6 uses 128-bit addresses and was developed to provide a much larger address space.

Common DNS records

  • A record: maps a domain name to an IPv4 address.
  • AAAA record: maps a domain name to an IPv6 address.
  • CNAME record: makes one DNS name an alias of another canonical name.
  • MX record: identifies mail servers responsible for receiving email for a domain.
  • TXT record: stores text information, commonly used for domain verification and email security policies.
  • NS record: identifies the authoritative name servers for a DNS zone.
  • CAA record: specifies which certificate authorities may issue certificates for a domain.

DNS resolution

DNS resolution is the process of finding the DNS information associated with a name. A resolver may consult cached information or query DNS servers through the hierarchy until it obtains an answer. DNS propagation is a common informal term for the time taken for DNS changes to become visible through caches and resolvers; it is not a single global switch being updated everywhere at once.

Bandwidth, latency and uptime

  • Bandwidth: the data-transfer capacity of a network connection over a period of time.
  • Latency: the time taken for data to travel between points or for a request to receive a response.
  • Throughput: the actual rate at which data is successfully transferred or processed.
  • Uptime: the period during which a service is operational and available.
  • Downtime: a period when a service is unavailable or not functioning as intended.
  • SLA — Service Level Agreement: a formal agreement defining expected service levels and responsibilities between a provider and customer.

12. Protocols, Security and Certificates

TCP/IP — Transmission Control Protocol / Internet Protocol

TCP/IP refers to the family of networking protocols used to communicate across interconnected networks. IP handles addressing and routing packets between networks. TCP provides a reliable, ordered byte stream between endpoints, including retransmission where necessary.

UDP — User Datagram Protocol

UDP is a transport-layer protocol that sends datagrams without TCP's built-in delivery, ordering and retransmission guarantees. It is useful where low overhead or application-controlled delivery behaviour is important.

HTTP versus HTTPS

HTTPS means HTTP Secure. It is HTTP communication protected using TLS. HTTPS helps provide confidentiality, integrity and server authentication for data exchanged between a client and the authenticated server endpoint.

SSL and TLS

  • SSL — Secure Sockets Layer: an older security protocol that has been deprecated and should not be used for modern secure connections.
  • TLS — Transport Layer Security: the modern cryptographic protocol used to secure network communications, including HTTPS.
  • SSL certificate: a common industry phrase for a digital certificate used with HTTPS, although modern HTTPS uses TLS rather than SSL.
  • Digital certificate: an electronic document that binds an identity, such as a domain name, to a public key and is digitally signed by a certificate authority or another trusted issuer.
  • CA — Certificate Authority: an organisation trusted to issue and sign digital certificates under a defined trust system.
  • Public key: a cryptographic key that can be shared and is used in public-key cryptography.
  • Private key: a secret cryptographic key that must be protected and is paired with a public key.
  • Encryption: transforming information so that it cannot be understood without the appropriate key.
  • Hashing: producing a fixed-length digest from data. Hashing is not encryption and is not designed to be reversed.

Common web security terms

  • Input validation: checking that incoming data has the expected type, structure, length and allowed values.
  • Output encoding: converting data into a safe representation for the context in which it will be displayed or inserted.
  • XSS — Cross-Site Scripting: a vulnerability in which attacker-controlled script content executes in another user's browser in the context of a trusted site.
  • SQL injection: a vulnerability in which untrusted input changes the meaning of a database query. Parameterised queries help prevent it.
  • CSRF — Cross-Site Request Forgery: an attack that tricks a user's browser into sending an unwanted authenticated request to a site.
  • Rate limiting: restricting how frequently a client can make requests to a service.
  • Firewall: a security control that filters network traffic according to defined rules.
  • WAF — Web Application Firewall: a security control designed to inspect and filter HTTP traffic to web applications.
  • Backup: a separate copy of data or system information that can be used for recovery.
  • Least privilege: giving a user, process or service only the permissions necessary to perform its assigned task.
Security reminderHTTPS protects data in transit, but it does not automatically make an application secure. Applications still need secure authentication, authorisation, validation, access controls, dependency updates, backups and careful secret management.

13. Deployment and Publishing

Deployment

Deployment is the process of making a software application or website available in a target environment. It may involve building files, configuring servers, setting environment variables, connecting databases, applying migrations and directing traffic to the new version.

Development, staging and production

  • Development environment: the environment where developers write code, experiment and test changes during construction.
  • Testing environment: an environment used to check whether software behaves correctly under defined conditions.
  • Staging environment: a pre-production environment intended to resemble production and used for final checks before release.
  • Production environment: the live environment used by real users.

Build and release terms

  • Source code: the human-readable instructions written by developers.
  • Build: the process of transforming source files and dependencies into output suitable for running or distribution.
  • Artifact: a produced file or package from a build, such as compiled code, a bundle or a container image.
  • Release: a version of software made available for deployment or use.
  • Rollback: returning an application or deployment to a previous known version after a problem.
  • CI — Continuous Integration: a practice of frequently integrating code changes and automatically running checks such as builds and tests.
  • CD — Continuous Delivery / Continuous Deployment: Continuous Delivery keeps software ready for release through automated processes; Continuous Deployment automatically releases changes that pass the required pipeline.
  • CI/CD pipeline: an automated sequence of steps for building, testing and preparing or deploying software.
  • Environment configuration: settings supplied to an application for a particular environment, such as database connection details and service endpoints.
  • Secret: sensitive information such as passwords, API keys, private keys or tokens that must not be exposed in public source code.

Git and collaboration

  • Version control: tracking changes to files over time so developers can inspect history and coordinate work.
  • Repository: a project location managed by a version control system.
  • Commit: a recorded set of changes in a version control repository.
  • Branch: an independent line of development within a repository.
  • Merge: combining changes from different branches.
  • GitHub / GitLab: platforms that host Git repositories and provide collaboration and development workflow tools.

Containers and virtualisation

  • Virtualisation: creating virtual versions of computing resources, such as servers or operating systems, on physical hardware.
  • Virtual machine (VM): a software-based computer that runs its own operating system in a virtualised environment.
  • Container: an isolated application execution environment that packages an application with its required dependencies while sharing the host operating system kernel.
  • Docker: a platform and toolset for building, distributing and running containers.
  • Container image: a packaged, read-only template used to create containers.
  • Orchestration: automated management of multiple containers or services, including scheduling, scaling and recovery.
  • Kubernetes: a container orchestration platform for managing containerised workloads and services.

Monitoring and maintenance

  • Monitoring: collecting and observing information about application health, availability and performance.
  • Metrics: numerical measurements such as response time, error rate, memory use and request volume.
  • Tracing: following a request as it travels through multiple application components or services.
  • Incident: an event that causes or risks service interruption, degradation or security impact.
  • Patch: a software update that corrects defects or security weaknesses.
  • Scalability: the ability of a system to handle increased workload by adding or using resources effectively.
  • Horizontal scaling: increasing capacity by adding more instances or machines.
  • Vertical scaling: increasing the resources of an existing machine, such as CPU or memory.
  • Cache: a temporary storage layer that keeps frequently used data so it can be accessed more quickly.
  • CDN — Content Delivery Network: a distributed network of servers that delivers content from locations closer to users, helping reduce latency and improve availability.

14. Common Website Architecture Patterns

Client-server architecture

Client-server architecture is a model in which client applications request services or resources from server systems. A web browser is commonly a client, while a web server or backend application provides services.

Two-tier architecture

A two-tier architecture separates a client application from a server or data service. The client communicates directly with the second tier. In a simple database application, the client may communicate directly with a database server.

Three-tier architecture

A three-tier architecture separates an application into presentation, application logic and data tiers.

  • Presentation tier: the user interface, commonly the browser-based frontend.
  • Application tier: the backend logic that processes requests and applies rules.
  • Data tier: the database or storage system that manages persistent information.

Monolithic architecture

A monolithic application is built and deployed as one main application unit, even if its internal code is divided into modules. Monoliths can be straightforward to develop and operate, especially for smaller systems, but a large monolith may become harder to maintain if boundaries are poorly designed.

Microservices architecture

Microservices architecture structures an application as a collection of relatively small, independently deployable services. Each service handles a defined business capability and communicates with other services through agreed interfaces. This can support independent scaling and deployment, but introduces network, monitoring and operational complexity.

Serverless architecture

Serverless architecture uses cloud-managed services and execution environments where the provider manages much of the underlying infrastructure. Developers focus more on application code and service configuration. Serverless does not mean that physical servers are absent.

Headless architecture

A headless system separates the content or application backend from the frontend presentation layer. The backend exposes content or functionality through an API, allowing different frontends — such as websites, mobile applications or kiosks — to use the same source.

15. Website Quality, Accessibility and Search Visibility

UI — User Interface

The user interface is the part of a system through which a person interacts with it. It includes visible controls, navigation, text, forms and feedback.

UX — User Experience

User experience describes the overall experience a person has when using a product or service. It includes usefulness, ease of use, accessibility, clarity, trust and satisfaction.

Accessibility

Web accessibility is the practice of designing and developing websites so that people with different abilities can perceive, understand, navigate and interact with them. It includes keyboard access, meaningful headings, labels, text alternatives for meaningful images, sufficient contrast and compatibility with assistive technologies.

WCAG — Web Content Accessibility Guidelines

WCAG is a set of internationally recognised guidelines for making web content more accessible. Its four main principles are Perceivable, Operable, Understandable and Robust (POUR).

SEO — Search Engine Optimisation

SEO is the practice of improving a website's ability to be discovered and understood through search engines. It includes useful content, descriptive page titles, semantic structure, crawlable links, performance, mobile usability and accurate metadata. SEO does not guarantee a particular ranking.

Performance terminology

  • Page load time: the time required for a page and its important resources to load.
  • Core Web Vitals: a set of user-experience performance metrics published by Google, including loading, interactivity and visual stability measurements.
  • Lazy loading: delaying the loading of non-critical resources until they are needed or likely to be viewed.
  • Minification: removing unnecessary characters from code files to reduce file size without changing intended behaviour.
  • Compression: encoding data in a way that reduces the amount of data transferred or stored.
  • Optimisation: improving a website's performance, accessibility, reliability, security or maintainability.

16. The Complete Website Development Process

  1. Requirement gathering: identify the website's purpose, users, content, features, constraints and expected outcomes.
  2. Planning: define scope, page structure, navigation, technology choices, responsibilities and delivery milestones.
  3. Information architecture: organise content into sections and establish how users will find information.
  4. Wireframing: create simplified layouts showing the placement and hierarchy of page elements before detailed visual styling.
  5. Visual design: define colours, typography, spacing, imagery, components and responsive behaviour.
  6. Frontend development: implement page structure, styles, interactions and browser-side communication.
  7. Backend development: implement routes, business rules, validation, authentication, data access and APIs where required.
  8. Database design and integration: define data structures and connect application operations to storage systems.
  9. Testing: check functionality, usability, accessibility, responsiveness, security and compatibility.
  10. Deployment: build and configure the application in its target hosting environment.
  11. Domain and DNS configuration: connect the domain name to the correct hosting or service endpoints.
  12. Monitoring and maintenance: observe the live website, correct faults, update dependencies, maintain backups and improve the system.
Remember the orderUnderstand the problem first, design the solution, build the frontend and backend, test the complete system, deploy it, then monitor and maintain it. Publishing code is not the end of website development.

18. Summary of Key Concepts

  • Website design plans the appearance, organisation and user experience of a website.
  • Website development implements the website through structure, styling, programming, data handling and testing.
  • HTML structures content, CSS presents it and JavaScript adds behaviour.
  • XML, JSON, SVG, XAML, YAML and Markdown serve different purposes; they are not all programming languages or interchangeable formats.
  • Frontend development focuses on the browser-facing interface; backend development handles server-side logic and data operations.
  • Frameworks provide structure; libraries provide reusable functionality; runtimes execute programs; packages distribute code.
  • HTTP defines request-and-response communication, while APIs define how software components interact.
  • Synchronous operations wait for completion in the current flow; asynchronous operations allow other work to continue while results are pending.
  • Databases store and organise application data.
  • Server-side programming processes requests, applies rules and returns responses.
  • Hosting provides computing and network resources; a domain name provides a readable address; DNS helps resolve that name.
  • HTTPS uses TLS to protect communication, but application security requires more than encryption in transit.
  • Deployment publishes an application to a target environment, while monitoring and maintenance keep it reliable after release.
